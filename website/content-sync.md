# Content Sync Architecture

This document explains how the website stays in sync with the GitHub repository.

## Data flow

```
GitHub repo (marxwood/semantic-system-design)
    │
    ├── book/graph-index.jsonld   ← Navigation graph (250 nodes, role weights)
    ├── book/<cluster>/<file>.md  ← Chapter content (markdown + frontmatter)
    └── README.md                 ← Homepage content
         │
         ▼  (raw.githubusercontent.com / GitHub API)
    Server cache (5-minute TTL)
         │
         ▼  (tRPC procedures)
    React frontend
         │
         ▼
    Reader at semanticdesign.systems
```

## Cache invalidation

The server maintains an in-memory cache keyed by file path. Each entry has a 5-minute TTL.

On a GitHub push event, the webhook at `/api/webhook/github` calls `invalidateCache()` and `invalidateGraphCache()`, clearing all entries immediately.

## Graph index

The `book/graph-index.jsonld` file is the single source of truth for:
- All node IDs and their names
- Cluster membership
- Role-weighted links between nodes
- File paths for each node's markdown content

It is regenerated by running:
```bash
npm run graph:index
```

This tool (`tools/generate-graph-index.mjs`) reads all `.md` files in `book/`, merges them with the canonical TOC (`book/toc.v2.jsonld`), and computes role weights based on cluster relationships.

## Node ID to file path mapping

The server resolves file paths from URN node IDs using two strategies:

1. **From graph-index**: if the node has a `ssd:file` property, use it directly
2. **From URN pattern**: derive the path from the URN structure:
   - `urn:ssd:toc:v2:foundations:01` → `book/foundations/foundations-01.md`
   - `urn:ssd:toc:v2:entry:foundations` → `book/entry/entry-foundations.md`
   - `urn:ssd:toc:v2:epilogue` → `book/epilogue.md`
   - `urn:ssd:toc:v2:readingpath:designer` → `book/reading-paths/path-designer.md`

## Adding content

When you add a new chapter:

1. The file appears in the GitHub tree API response
2. The graph-index must be regenerated and committed to include the new node
3. The website will discover the new node via the graph-index on the next cache refresh

Chapters that exist in the graph-index but have no corresponding markdown file are shown as "not yet written" placeholders on the website — this is intentional for the work-in-progress state.
